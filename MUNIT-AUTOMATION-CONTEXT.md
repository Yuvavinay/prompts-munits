Current release: **12.1.0**. This context is self-contained for continuing the build in another session, including a Claude session. Read it together with the current three prompt files before making changes; do not resume an older release's implementation by memory.

The latest handoff archive is munit-automation-final.zip. It contains this context and the munit-automation-v12.1/ folder with:

Target host: existing VS Code chat with GitHub Copilot, Agent selected, Auto or the user's existing model. Invoke /munit-generate all, a source XML filename, a comma-separated list, or errors. Omitted scope means all. Install the three definitions together in the documented user-level location outside Maven applications, then start a fresh chat. Commands are embedded in Markdown; no helper script, new extension or new package installation is required. There is no separate refresh prompt.

The architecture is model-neutral: intended for Claude, GPT and Gemini through an agent environment providing filesystem/search/edit/terminal tools. No model is pinned, no provider-specific API is used and no subagent capability is required. A plain chat without these tools can review the package but cannot execute it against a local project. Identical reliability across all models, versions and API complexities has NOT been proved or guaranteed.

## Latest user requirements and decisions

It does not extract RAML, create indexes or analyse DWL. Outbound HTTP calls and source-less callable helpers do not determine routing. Default all needs no interaction menu.
2. Select the MAIN API from pom.xml, local parent/profile/property/dependency metadata and the APIKit contract reference. Resolve its exact groupId/artifactId/version/type/classifier and effective local Maven repository, normally .m2/repository. Repository URLs are not local paths. The known common-library name NEVER selects or replaces this root artifact. No downloads or Maven-cache edits.
3. The user says csp-dhisp-common-api-library.raml is already provisioned in .m2. Treat that as an expected prerequisite and verify exact availability during execution; a prompt cannot make an absent file exist. If required headers are unresolved, automatic local recovery is mandatory BEFORE accepting an empty header map or a source-backed fallback. Check the dependency's own exact identity/version in loose files AND cached ZIP entries, then evidenced wrapper/source/Exchange references and a narrow repository index. A missing file inside the main API ZIP does not mean the library is absent from .m2. Never substitute another version or a same-named unrelated file.
4. Follow the actual endpoint method's is entries, parameters and uses aliases into the selected library traits and included/nested definitions. Extract verified dependency archives to fresh external temp, preserving includes; loose cache files may be read without edits. Merge actual applicable resource/resourceType/security/method declarations according to the RAML version. Do not copy every header in the common library or response headers. An empty method is list adds no traits and does not cancel resource-applied traits. Do not invent a common-library dependency if the method is already fully resolved without it.
5. Record method/path, actual is entries, main/dependency evidence, alias/trait chain, effective required headers and value/type/enum evidence. A complete empty map requires reading all applicable declarations. Use valid examples/defaults/enums or existing test-property expressions, never invented credentials. 6. Every extraction, plan, temporary script, staging area and optional runtime copy stays in verified physical OS temp outside the application. Extraction guards additionally reject a temp parent inside the Maven repository or user .m2 directory. Never extract into source, target or .m2. If configured TEMP/TMPDIR is unsafe, choose another existing native-system-temp parent outside all protected roots using the documented assignment, without changing environment settings.
7. Continue automatically after evidence recovery and through every selected owner. Do not stop after discovery, ask what to do next, generate only the first endpoint, or substitute one test per suite for recursive coverage. Optional enabled subagents may perform bounded read-only analysis/review; the parent verifies results and is the sole writer. Complete failed delegation locally with the same serial workflow.

## Full generation contract to preserve

- HTTP all includes every APIKit method/path owner, with endpoint-specific -test-suite.xml files. File/list selection resolves all items, reverse callers and cross-file dependencies. Discover APIKit and main error-handler bodies independently: source-required apikit-error-test-suite.xml and error-test-suite.xml must be generated, with every feasible matcher/body path. Local handlers stay with the owning entry. Separate modules retain separate ownership.
- After main extraction and dependency/header recovery, recursively read every reached XML flow/sub-flow, scope, handler reference, DWL script/import/function and relevant data reference. Cache reads by current content, retain each call context and full prefix/suffix. Use active-cycle detection and source-proven termination, with no arbitrary traversal/test cap.
- Enumerate full feasible paths before XML. Cover choice when/otherwise and nested/sequential combinations; scatter-gather all-route success and per-route alternatives while mocking all concurrently active calls; foreach/parallel-foreach/batch representative and behavior-changing cases; try/handlers; cache miss/hit; until-successful success/retry exhaustion; and supported observable async/batch completion. Account for every executable processor occurrence. Target measured coverage 100% for flows with at most 25 executable doc:id processors and at least 80% for larger flows; planned paths are not measured coverage.
- Drill resolved flow-ref bodies rather than mocking them. Mock actual external operations across the complete path, including handler bodies and concurrent routes: HTTP, database, Salesforce, WSC, file/SFTP/FTP, object store, MQ/JMS/VM and evidenced custom outbound operations. Select exact current source doc:id/doc:name when present; never guess selectors or mock the test HTTP client. Unresolved static references need an explicit NOTE and coverage gap. Never mock real transforms, scopes, handlers or loggers.
- Every returned mock payload uses a literal MunitTools::getResourceAsString('out/<file>.json'), parsed to the evidenced type where needed. No bare payload return or inline JSON. Preserve target/targetValue, attributes and errors. then-return child order is variables, payload, attributes, error, omitting unused children according to schema. Mock-when belongs only in behavior; the empty-branch comment is allowed only for an entire provably connector-free path.
- Collect every selected RAML base request example and all needed variants before writing suite XML. Preserve JSON examples verbatim or faithfully serialize YAML examples. Branch variants change only actual predicate inputs and satisfy complete ancestor/conjunction/earlier-false conditions plus schema constraints, types and enums. Backend-controlled branches change backend fixtures. All base/variant fixture files are staged as a batch and gated before publication.
- in/ represents actual entry payloads. For non-HTTP use first-entry XML/DWL consumers; keep attributes, flow-derived data and backend results distinct. out/ always contains raw connector output read by downstream code, not transformed response. Only HTTP with proved exactly-payload pass-through may use a RAML response example. Fixture manifest v2 and embedded required/type/enum gates remain; explicit APIKit negative inputs have separate roles and expected failures. No parser dependency is installed.
- Every suite imports test-config.xml once and has unique munit:config. Shared configuration lives at src/test/resources/test-config.xml, derived from actual app/test configuration. Copy exactly app-properties-test.yaml and app-secrets-test.yaml from their actual production resource locations to test properties, byte-identically. Do not copy/create dev/qa/prod/constants/error YAML files or delete existing unrelated files to satisfy the rule.
- XML begins with one declaration and one Mule root, no BOM/leading whitespace. Optional generated doc:id values must be unique lowercase hexadecimal UUIDs. Declare only used namespaces. Names begin SUITE_BASE-, never happy-path/error-path/default-choice. Each test has exactly four INFO payload loggers and the prescribed single dw::test::Asserts non-null assertion. Preserve useful existing custom assertions and report conflicts instead of deleting them. Do not fabricate non-null payloads when actual behavior returns null.
- REST Mode A enables main+public sources, Mode B main only and APIKit router mock, Mode C main+public with the real router and backend error. Enable sources first; payload-only set-event first in execution. Execute HTTP requests; the specific evidenced direct raise-error sub-flow exception is not routing coverage. Error requests have the last-child response validator accepting 200..599. Mock handler external calls rather than the handler. Non-HTTP disables entry sources and invokes actual processing without inheriting REST source/header rules.
- Existing valid selected tests and fixtures remain byte-for-byte and timestamp unchanged. Compare implementation, scenarios, selectors, headers and fixtures against current source; add missing cases and narrowly patch stale selected content. Preserve unrelated tests and check shared-fixture consumers. Do not delete/disable tests to achieve green. Recheck source/destination hashes and re-read every written file before declaring completion.
